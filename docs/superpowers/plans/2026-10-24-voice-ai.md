# Conversational Voice AI (Day 4) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement real-time two-way browser voice conversation using WebRTC with ephemeral session security, server-side route handlers, and authoritative appointment tool execution over WebRTC DataChannel.

**Architecture:** Provider-neutral `VoiceProvider` contract in `src/providers/voice/`, OpenAI Realtime adapter in `src/providers/voice/openai-realtime-adapter.ts`, Next.js Route Handlers in `src/app/api/v1/voice/`, and client-side WebRTC manager in `src/features/voice/`. All external HTTP and WebRTC calls are mocked in tests for fast, deterministic execution.

**Tech Stack:** TypeScript, Bun >= 1.4.3 (`bun@1.4.4`), Next.js 16+ App Router, React 19+, native `fetch`, WebRTC API standards.

---

## Global Constraints

- Keep frontend and backend in this single repository.
- Use `bun check`, `oxlint`, and `oxfmt`; never use ESLint or `tsc --noEmit`.
- Never expose the master OpenAI API key to the browser client; issue short-lived ephemeral session tokens from `POST /api/v1/voice/session`.
- Tool calls triggered by voice must be executed authoritatively on the server via `POST /api/v1/voice/tools`, reusing `AppointmentService` so junior dentist restrictions (cannot perform Services C, D, E) and clinic working hours are strictly enforced.
- All code comments, docstrings, inline notes, commit messages, and documentation must be written in English.
- Tests must run offline with `bun test` without requiring live OpenAI API keys or browser hardware.

**Interfaces:**
```ts
export type VoiceSessionConfig = {
  model: string;
  voice: string;
  modalities: Array<"text" | "audio">;
  instructions: string;
  tools?: unknown[];
  temperature?: number;
  inputAudioTranscription?: {
    model: string;
  };
  turnDetection?: {
    type: "server_vad";
    threshold?: number;
    prefixPaddingMs?: number;
    silenceDurationMs?: number;
  } | null;
};

export type VoiceSessionResponse = {
  sessionId: string;
  clientSecret: string;
  model: string;
  voice: string;
  expiresAt?: number;
};

export type VoiceProvider = {
  createSession(customConfig?: Partial<VoiceSessionConfig>): Promise<VoiceSessionResponse>;
};

export class VoiceProviderError extends Error {
  readonly provider: string;
  readonly operation: string;
  readonly status?: number;
  constructor(provider: string, operation: string, message: string, status?: number) {
    super(`[${provider}:${operation}] ${message}`);
    this.name = "VoiceProviderError";
    this.provider = provider;
    this.operation = operation;
    this.status = status;
  }
}
```

## Task 2: OpenAI Realtime adapter with ephemeral session creation

**Files:**
- Create: `src/providers/voice/openai-realtime-adapter.ts`
- Test: `tests/openai-realtime-adapter.test.ts`

**Interfaces:**
- `OpenAIRealtimeAdapter`: implements `VoiceProvider`.
  - Takes `apiKey`, optional `baseUrl` (default: `https://api.openai.com/v1`).
  - `createSession(customConfig?: Partial<VoiceSessionConfig>)`: calls `POST ${baseUrl}/realtime/sessions` with `Bearer ${apiKey}`.
  - Passes `SYSTEM_PROMPT` as default instructions and `APPOINTMENT_TOOL_DEFINITIONS` as default tools.
  - Normalizes OpenAI response (`client_secret.value`, `id`, `model`, `voice`).
  - Handles 401 Unauthorized, 429 Rate Limit, and network errors without leaking API keys.

**Route Specifications:**
- `POST /api/v1/voice/session`:
  - Returns `{ success: true, data: VoiceSessionResponse }` or 500 `{ success: false, error: string }`.
- `POST /api/v1/voice/tools`:
  - Body: `{ toolName: string, arguments: Record<string, unknown> }`.
  - Dispatches tool via `executeAppointmentTool(appointmentService, toolName, arguments)`.

## Task 4: Client-side WebRTC voice session manager & hook

**Files:**
- Create: `src/features/voice/voice-session-manager.ts`
- Create: `src/features/voice/use-realtime-voice.ts`
- Test: `tests/voice-session-manager.test.ts`

**Capabilities:**
- `VoiceSessionManager`:
  - State machine: `disconnected` | `connecting` | `connected` | `speaking` | `listening` | `error`.
  - Handles WebRTC DataChannel message processing:
    - Parses JSON events from `oai-events`.
    - When `response.function_call_arguments.done` is received: dispatches tool call to `/api/v1/voice/tools`.
    - Formats tool output as `conversation.item.create` (type `function_call_output`).
    - Sends `response.create` so assistant speaks result.
  - Audio track management: mute/unmute, disconnect, cleanup.
- `useRealtimeVoice`: React hook wrapping `VoiceSessionManager` with reactive state (`status`, `isMuted`, `error`, `transcript`).
